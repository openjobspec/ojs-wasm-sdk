### Feature gates

- `edge_cloudflare` gates `CloudflareClient`, `KVNamespaceRef`, and
  `D1DatabaseRef`.
- `edge_deno` gates `DenoClient`.
- `edge_vercel` gates `VercelEdgeClient`.
- `edge_all` enables all three.
- `service_worker`, `encryption`, and `schema` also gate their corresponding
  modules and heavy dependencies, enabling meaningful dead-code elimination.
- Defaults enable `edge_all`, `service_worker`, `encryption`, and `schema`, so
  every advertised 0.5.0 generated JS/declaration symbol remains present.
  `background_sync_tag_prefix` is the only additive default export.
- Generated JS and declarations were checked for default, no-default,
  individual edge, all-edge, service-worker, encryption, and schema builds.

### Durable Background Sync

- Pending jobs are stored in IndexedDB (`openjobspec-background-sync`,
  `pending-jobs`) before `SyncManager.register()` is called.
- Records are keyed by the generated sync tag and survive client/Service Worker
  recreation.
- The canonical prefix exists once in Rust and is exposed through
  `background_sync_tag_prefix()` for docs/examples/event filtering.
- A five-minute IndexedDB lease serializes concurrent processors. Explicit
  enqueue failures release the lease and retain the record.
- A record is deleted only after a successful, parseable enqueue response.
- Missing `ServiceWorkerRegistration`/`SyncManager` returns an explicit error;
  no fake scheduled tag is returned.
- If registration fails after persistence, the error includes the retained tag
  for manual recovery.
- Browser tests cover unsupported SyncManager, worker recreation, failed-send
  retention, successful deletion, and concurrent lease rejection.
- Delivery remains at-least-once across the unavoidable crash window between
  server acceptance and the IndexedDB delete commit; this is documented.

### Encryption and schema correctness

- Hex decoding operates on bytes, rejects non-ASCII input, and never slices a
  UTF-8 string at arbitrary byte offsets.
- Nonce generation returns `Result`; `getrandom` failures propagate through the
  encryption result to `JsValue`.
- An injectable entropy seam verifies public-path error propagation.
- Native and browser tests cover non-ASCII keys, invalid hex, entropy failure,
  and non-trapping behavior.
- JSON Schema `integer` now accepts zero-fraction representations such as
  `1.0`, `-0`, and `1e0`.
- Decimal/exponent classification rejects fractional values, values outside
  the supported signed/unsigned integer range, and non-finite/overflow input.

## Release size

Release settings are `opt-level = "z"`, fat LTO, one codegen unit,
`panic = "abort"`, symbol stripping, and converged `wasm-opt -Oz` with enabled
WASM features. `aes-gcm` disables unused default features.

CI-equivalent deterministic measurements use `gzip -cn`:

| Build | Features | Raw bytes | Gzip bytes |
|-------|----------|----------:|-----------:|
| Core | `--no-default-features` | 270,077 | 109,727 |
| Core + Service Worker | `service_worker` | 304,669 | 123,117 |
| Core + encryption | `encryption` | 299,297 | 121,435 |
| Core + schema | `schema` | 287,139 | 116,978 |
| Core + Cloudflare | `edge_cloudflare` | 283,603 | 115,302 |
| Core + Deno | `edge_deno` | 277,778 | 113,267 |
| Core + Vercel | `edge_vercel` | 278,838 | 113,665 |
| Core + all edge clients | `edge_all` | 289,580 | 117,418 |
| ABI-compatible default | default features | **370,278** | **149,733** |

The prior branch artifact was 455,448 raw / 158,396 gzip. Safe optimization
reduced this by 85,170 raw bytes (18.70%) and 8,663 gzip bytes (5.47%), despite
adding durable IndexedDB support.

### Regression gate

The previous 51,200-byte threshold was lower than the 109,727-byte no-default
core and therefore could not distinguish a regression from the required
feature baseline. It has been replaced with a 151,552-byte (148 KiB)
deterministic-gzip budget:

`151,552 - 149,733 = 1,819 bytes headroom`

The current artifact passes. CI still exits non-zero for any build above the
budget, leaving approximately 1.2% headroom for toolchain variance and making
future growth an explicit review decision.

### Performance conclusion

This is not an encryption-only overage: the no-default core is already 109,727
bytes gzip. A named pre-bindgen `twiggy monos` build attributes 76,899 raw bytes
(approximately 72,613 bytes of monomorphization bloat) to 62
`future_to_promise` wrappers generated for the public async methods across the
browser, generic-edge, runtime-specific, Service Worker, queue, durable, and
subscription surfaces. serde/JSON, allocator, error formatting, and the
required runtime glue make up the remaining core.

Meeting 50 KiB would require at least one public architecture/product decision:

1. make the default package minimal and remove established default exports;
2. split browser/edge/Service Worker/encryption surfaces into separate npm
   artifacts;
3. replace repeated WASM async class methods with JS forwarding/facades; or
4. replace the synchronous Rust AES API with async WebCrypto (a public API
   change).

Those options change default ABI or feature parity and were not applied
automatically. Rust `opt-level = "s"` and `3`, additional `wasm-opt -Os`,
`-O4`, strip/vacuum, and closed-world trials were measured; none materially
improved the current `z` plus converged `-Oz` profile. Detailed evidence and
feature composition are recorded in `docs/BUNDLE_SIZE.md`.
